# Data Model
All tenant-owned records carry organization_id, created_at, updated_at, retention policy and explicit access checks. Database PKs use UUID/ULID.
Tables: users; organizations; memberships; roles; business_profiles; brand_assets; offers; product_catalog_items; oauth_connections (encrypted credentials); ad_accounts; growth_objectives; strategies; creative_assets; campaign_proposals; approval_requests; budget_policies; campaigns; ad_sets; ads; performance_snapshots; leads; lead_events; consent_receipts; conversations; messages; appointments; opportunities; sales_outcomes; attribution_events; experiments; ai_runs; tool_intents; provider_jobs; idempotency_records; billing_subscriptions; audit_events; outbox_events.
Constraints: (organization_id, external_provider_id) uniqueness where applicable; optimistic revisions for approvals; immutable ledger for spend and consent events; hard limits on currency precision; serialized idempotent publishing. Strongly separate raw PII from analytical aggregates. Enforce migrations under test.
